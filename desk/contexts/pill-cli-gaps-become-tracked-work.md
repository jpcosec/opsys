# Guardrail: CLI gaps become tracked work

## What

_Define the context or guardrail this pill carries._

When real CLI validation exposes a missing behavior, broken path, or usability gap, turn that finding into explicit tracked work instead of leaving it in chat history or operator memory.

## Why

_Explain why this context matters for safe execution._

CLI validation only improves the workflow if discovered gaps become routable tasks, issues, or inbox items with enough evidence to revisit them safely.

## When

_Describe when an agent should apply this pill._

Apply this pill whenever a task exercises real CLI paths, capability audits, operator-manual slices, or workflow discovery tests that might expose missing command behavior.

## Where

_Name the files, surfaces, or scope this pill applies to._

Applies to CLI validation tasks, desk task promotion, issue capture, inbox routing, and any docs that claim an operator path works.

## How

_Describe the correct way to apply this guidance._

Record the failing command, expected behavior, actual behavior, and affected surface, then route the gap into the appropriate tracked work surface before treating the investigation as complete.

## How Not

_Describe the shortcut or failure mode to avoid._

Do not leave discovered CLI gaps only in transient notes. Do not let documentation continue to claim a path works after validation exposed a real missing behavior.
