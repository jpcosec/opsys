# Canonical runtime artifact policy

ID: question-canonical-runtime-artifact-policy
Status: resolved (2026-09-24)

## Question

Which generated runtime artifacts are canonical, ignored, committed, regenerated, or treated as disposable state?

## Surfaces

- `.sldb/runtime/knowledge_graph.kg.json`
- `.sldb/runtime/knowledge_graph.nx.json`
- self-reflection reports
- materialization manifests
- spec2viz projections
- generated docs or diagrams

## Needs Answer Before

- CI integration
- graph runtime stability
- generated artifact closeout checks

---

## Answer (2026-09-24)

The policy is already in force; it was written in `.gitignore` and in the run
evidence rules, not here.

| Surface | Policy |
| --- | --- |
| `.sldb/runtime/` (graph snapshots, caches, locks, journal) | generated, ignored, rebuilt on demand by `deskops graph build` |
| `runs/subagents/*/` evidence (board, task, next, graph, git status, result summary) | committed: it is the audit trail a closing commit links to |
| `runs/subagents/*/session.jsonl` | ignored: transcripts are large and rewritable, the digest is what matters |
| `runs/subagents/index.jsonl` | committed: it is the index of the above |
| spec2viz projections, generated diagrams | generated from their specs, never edited by hand |
| materialization manifests | generated by the materializer; the source atoms are canonical |

The rule behind the table: a file that can be regenerated from a tracked source
is not tracked, and a file that records that something happened is tracked.

See `desk/drawer/questions/question-herdr-runtime-open-decisions.md` for the
transcript decision and `.gitignore` for the implementation.
